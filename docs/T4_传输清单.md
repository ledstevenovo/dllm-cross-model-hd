# T4 实例：文件传输清单与实测记录

日期：2026-10-20。记录在本机（Windows）与 T4 实例之间**实际执行并校验通过**的传输与环境步骤。
本文只记录已验证的事实；未验证项明确标注。

## 0. 结论先行

**不需要传权重。** 项目代码与数据合计不到 4 MB，权重从实例侧 `hf-mirror.com` 直拉（实测 9.2 MB/s），比本地上传快。

需要上传的只有两个包：

| 包 | 大小 | 内容 |
|---|---|---|
| `dllm-t4-base.tgz` | 235 KB | `src/ scripts/ configs/ tests/ docs/ pyproject.toml uv.lock README.md HANDOFF.md STATUS.md .gitignore .gitattributes` + `data/raw_qa/subsets/` + `data/manifests/` + `data/README.md` |
| `dllm-t4-data.tgz` | 3.5 MB | `data/raw_qa/` 全量（解压 29 MB）+ `data/manifests/` + `data/README.md` |

**不需要上传**：`.git/`（4.2 MB）、`.venv/`、`.uvcache/`、`.uvpython/`、`.uvtools/`、`.uvbin/`、`_pyfix/`、`.tmp/`、`results/`（4 MB）、`data/raw_download/`（35 MB）。这些都可重建，或与 T4 任务无关。

## 2. 传输步骤（已执行，sha256 双端一致）

  --exclude='.git' --exclude='.venv*' --exclude='.uvcache' --exclude='.uvpython' \
  --exclude='.uvtools' --exclude='.uvbin' --exclude='.tmp' --exclude='.pipcache' \

## 3. 远端环境搭建（已执行）

### 3.1 网络：必须钉死国内源

| 目标 | 实测 |
|---|---|
| `pypi.org` | 200，但 **39 KB/s**（11.99 s 才返回 index 页面）|
| 清华 `pypi.tuna.tsinghua.edu.cn` | 200，**4.9 MB/s** |
| 阿里 `mirrors.aliyun.com/pypi` | 200，2.5 MB/s |
| `huggingface.co` | IPv4 可解析但 443 超时；须走镜像 |
| `hf-mirror.com` | 200，**9.2 MB/s**（实测下载 60 MB 分片）|

教训：`uv sync --locked` 用默认源会挂满 15 分钟不返回；换清华源后 12 秒完成。

### 3.2 装 uv

```bash
curl -4 -LsSf https://astral.sh/uv/install.sh | sh
export PATH=/root/.local/bin:$PATH     # uv 0.13.3
```

### 3.3 项目 CPU 环境

系统 Python 3.10 不满足 `requires-python = ">=3.12,<3.14"`，且无 pip。复用 conda 的 3.12.4：

```bash
cd /root/bayes-tmp/dllm-cross-model-hd
export PATH=/root/.local/bin:$PATH
export UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple

uv venv --python /opt/conda/bin/python .venv
uv lock                                   # 只改 registry URL；--locked 会失败
uv sync --locked

mkdir -p .tmp/pytest
uv run pytest                             # 75 passed
```

`uv lock` 的差异仅限 `revision = 3 -> 5`、registry URL 与 `upload-time` 字段，包版本未变。

### 3.4 推理环境（LLaDA，已验证）

系统已有 torch 2.5.1+cu124，避免重复下载 CUDA 版 torch：

```bash
uv venv --python /opt/conda/bin/python --system-site-packages /root/bayes-tmp/.venv-llada-t4

cat > /root/bayes-tmp/pip.conf <<'EOF'
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
trusted-host = pypi.tuna.tsinghua.edu.cn
timeout = 60
EOF

PIP_CONFIG_FILE=/root/bayes-tmp/pip.conf \
  /root/bayes-tmp/.venv-llada-t4/bin/python -m pip install \
  "transformers==4.38.2" accelerate bitsandbytes huggingface_hub \
  tokenizers safetensors sentencepiece einops
```

实测版本：transformers 4.38.2、accelerate 1.15.0、bitsandbytes 0.50.2、tokenizers 0.15.2、safetensors 0.8.0、huggingface_hub 0.36.2。

**NF4 算子验证已通过**（T4 上真实 forward）：

```python
lin = nn.Linear(256, 128, bias=False).cuda().half()
q = bnb.nn.Linear4bit(256, 128, bias=False, compute_dtype=torch.float16,
                      quant_type="nf4", quant_storage=torch.uint8).cuda().half()
q.weight = bnb.nn.Params4bit(lin.weight.data.clone(), requires_grad=False,
                             quant_type="nf4").cuda()
out = q(torch.randn(2, 256, device="cuda", dtype=torch.float16))
# -> torch.Size([2, 128]) torch.float16，通过
```

这只证明 bnb 的 4-bit 算子在 T4 上可用，**不证明 LLaDA/Dream 的自定义模型能整体以 NF4 加载**。

## 4. 下载权重

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/root/bayes-tmp/hf-cache
```

```python
from huggingface_hub import snapshot_download
snapshot_download("GSAI-ML/LLaDA-8B-Instruct",
                  revision="08b83a6feb34df1a6011b80c3c00c7563e963b07",
                  allow_patterns=["*.json", "*.safetensors", "*.py", "*.txt", "*.model"],
                  max_workers=4)
```

注意：
- 必须带 `revision`，与 `configs/models/llada.json` 一致。
- LLaDA 的 `hf-mirror` 分片实测为 **6 个** `model-0000N-of-00006.safetensors`；此前用猜测文件名试过 `of-00004`，镜像返回 `Entry not found`。
- 未装 `hf_transfer`，用的是普通 HTTP 下载；实测速率波动较大。

### 4.1 LLaDA 下载完成记录（2026-10-20 22:55）

| 检查项 | 结果 |
|---|---|
| 耗时 | 6647 秒（1 小时 50 分），14 个文件 |
| 分片数 | 6，与 `model.safetensors.index.json` 的 `weight_map` 完全一致 |
| 张量总数 | 291（index 记录 291） |
| 分片字节 | 2109747184 / 2948598128 / 2986883656 / 2952797224 / 2919239128 / 2113931792 |
| 合计 | 16,031,197,112 B = 14.93 GB |
| safetensors 可读性 | 6 个分片全部 `safe_open` 成功；逐片张量数 34/20/127/60/29/21 |
| dtype | header 全为 BF16 |
| 残留 `.incomplete` | 0 |

落盘路径：

```
/root/bayes-tmp/hf-cache/hub/models--GSAI-ML--LLaDA-8B-Instruct/snapshots/08b83a6feb34df1a6011b80c3c00c7563e963b07
```

**注意 `refs/` 目录不存在**：使用显式 `revision=` 时 `snapshot_download` 不写 `refs/main`。因此后续加载
`from_pretrained` **必须显式传 `revision="08b83a6feb34df1a6011b80c3c00c7563e963b07"`**，否则会尝试联网解析 `main` 分支。

下载速率实测：起始 8–9 MB/s，中段跌到 1–2 MB/s，末段长尾低至 0.4 MB/s。单一镜像源无法改善。

## 5. 容量规划（关键风险）

| 项 | 占用 |
|---|---|
| LLaDA-8B BF16 原始权重 | ~16 GB |
| Dream-7B BF16 原始权重 | ~15 GB |
| `.venv-llada-t4` | 245 MB |
| `dllm-cross-model-hd/.venv` | 520 MB |

两套权重的**原始 checkpoint 合计约 31 GB**。`/root/bayes-tmp` 只有 50 GB，且 NF4 是**加载时量化**，磁盘上仍必须放原始权重。因此：

- 两个模型都下满后，`/root/bayes-tmp` 剩余空间会非常紧张；
- 若要在同一盘上同时保留两套权重 + 轨迹 + 缓存，需要清理，或先跑完 LLaDA 再删/移，再下 Dream；
- 不能假设根盘 48 GB 能兜底。
