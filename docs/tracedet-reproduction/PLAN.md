## 1. 先回答两个问题

**DynHD：做过方法级、小规模复现，不能说已完整复现论文。**

根据 [DynHD 实验总结](<../../reports/dynhd_reproduction_summary.md>)：

| 检查项 | 已有证据 | 限制 |
| --- | --- | --- |
| 代码与基础测试 | 36 个上游文件哈希一致；7 个官方测试、22 个 CPU 断言通过 | 证明实现与基础通路，不证明论文主表 |
| 真实模型采集 | LLaDA、Dream 各 200 题；各 5/5 hook 检查通过；记录器无干扰检查通过 | 仍是 pilot |
| 检测器训练与评测 | LLaDA 有效 194 题，训练/验证/测试 118/29/47；3 个训练种子平均 AUROC 0.8824 | 测试集很小 |
| Dream 结果 | 有效 178 题，训练/验证/测试 108/25/45；平均 AUROC 0.8093 | 测试集很小；共同测试问题仅 44 个 |
| 与论文的一致性 | 核心流程已走通 | Dream 使用 64 步、温度 0，而论文为 128 步、0.2；标签是规则签核，不是论文的 GPT-4o-mini |

上面的 0.8824、0.8093 是“检测器能否把对错回答排开”的指标，**不是大模型答题正确率**，也不是同协议的论文数字复现。后续 2000 题主项目实验不能自动算作 DynHD 原方法的全量复现。若补 DynHD，应另开任务：对齐其论文生成参数和标签，再扩数据、重复训练。

**TraceDet：值得做，方法/公开代码复现有可行基础；严格重现原表仍有条件和未知项。**

- 有论文、生成/打标/训练源码及部分权重；本地 56 个文件均与保存的 manifest 匹配。
- 不需要微调 7B/8B 基座模型。大模型只负责生成回答和记录过程，训练的是一个较小的检测器。
- 单卡 32GB 理论上有希望，但必须用最长提示词和原生成设置实测，不能预先承诺一定放得下。
- 公开快照有工程问题，也存在论文公式与实际实现不一致；缺原始样本 ID、完整原始数据和逐格最优配置，不能承诺获得一模一样的分数。

## 2. 不读论文也能理解它在做什么

把扩散语言模型想成一个“反复修改整张答卷”的学生。我们不只看交卷答案，还记录它每次修改时各个位置有多犹豫。

- **熵**：犹豫程度。几个词都差不多可能时熵高；几乎认定一个词时熵低。低熵也可能自信地答错。
- **轨迹**：把这些犹豫值排成表，纵轴是修改轮次，横轴是回答中的位置。
- **TraceDet**：学习哪些轮次更值得看，再判断最终答案是否有问题。监督信号只需要整条答案的对错，不要求人工标出“第几轮开始出错”。

例如，`T=64、L=64` 的回答产生一张 `64×64` 的熵表。不能把它先压成一个平均值或仅保留新揭示位置，再声称输入与论文一致。

这里要分清：**能预测错误，不等于已经证明哪一步导致错误**；挑出的时间片段是检测线索，不自动构成因果解释。

### 最重要的源码差异

1. 论文 Eq.6/7 是 Bernoulli KL 信息瓶颈正则；[TimeHalu 实现](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/models/TimeHalu.py#L35-L89>) 实际使用 L2 正则，分类部分还有原始预测损失与 Poly1 交叉熵。其熵分支使用软掩码概率，而不是采样出的硬掩码。**不要悄悄改成公式版再称为原代码复现。**
2. [L2Loss](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/utils/predictors/loss.py#L217-L223>) 是 `sqrt(sum(attn²))`；`gsat_r` 虽传入，但没有进入这条实际正则。代码路线不能把调整它解释为“验证了论文的先验保留比例”。
3. [调参入口](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/train_tuning.py#L79-L107>) 返回测试集 AUROC；若据此挑配置会污染测试。修为仅返回验证结果，最终测试集只在配置锁定后打开。
4. 原实现用第二列原始 logit 算 AUROC，不是 softmax 概率，两者排序未必相同。代码兼容分数与标准概率分数必须分别标明，不能默换。

若拿不到作者澄清，A 的最终名称应是“公开实现的独立复现（含披露的工程与评测修正）”，B 应叫“按论文公式重新实现”。

## 4. 固定数据、提示词与生成协议

### 4.1 规模：先小后大

下面训练条数来自 [公开数据加载器](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/DLLM_generate/data_loader.py#L25-L153>)，不声称已恢复论文实际使用的原始 ID。

| 数据集 | 训练 | 验证 | 测试 | 每模型、每长度回答数 |
| --- | --- | --- | --- | --- |
| TriviaQA | 2000 | 200 | 200 | 2400 |
| HotpotQA | 1300 | 200 | 200 | 1700 |
| CommonsenseQA | 2000 | 200 | 200 | 2400 |

- 核心目标：2 个模型 × 3 个任务 × 2 个长度 = **12 格**，共 **26000 条回答**，不含 pilot/冒烟、重试、额外生成种子、额外 CFG 设置或多次采样基线。
- 先完成 64 长度下 TriviaQA、HotpotQA 的两模型四格：8200 条；余下八格 17800 条。
- 论文主表这些格是分别训练和测试，不是训练一个模型后直接迁移到另一个模型。
- 同一问题在两模型、两长度下使用同一 split；不同题目的去重按问题 ID 和规范化文本双查。任何同题答案不得跨 train/dev/test。
- 固定数据集 revision、子集名称、抽样种子、样本 ID、原始提示词、参考答案；保存实际划分清单，而不是只写 seed=42。

### 4.2 不能省略的输入差别

- TriviaQA 使用作者的简短回答提示和答案标记，保留多个参考别名。
- HotpotQA 公开脚本只取**第一段上下文**并要求根据上下文回答，不是裸题，也不是完整支持材料。代码路线照此记录；若改为完整上下文，必须单列协议。
- CommonsenseQA 为五选一，保存选项顺序。原脚本的宽松子串判题仅作为代码兼容诊断，另做严格选项解析敏感性分析。

| 项目 | LLaDA | Dream |

| 模型 | GSAI-ML/LLaDA-8B-Instruct | Dream-org/Dream-v0-Instruct-7B |

## 5. 单卡 32GB 可行性与资源闸门

8B 模型 BF16 参数理论约 16GB（十进制），但还要加激活、注意力、词表 logits、运行时和 CFG 双分支。论文报告使用 NVIDIA A40；当前服务器的具体 GPU、驱动、空闲情况和模型缓存本轮未实时核验。

**执行原则：**大模型生成 → 卸载 → Qwen judge 打标 → 卸载 → 小检测器训练。不要让两个基座模型或生成模型与 judge 同时占卡。

- batch=1 起步，分别测短提示词及最长 HotpotQA 提示词，覆盖 L=64/128、LLaDA CFG=1。
- 只保存紧凑熵、必要 token/元数据；不长期保留每轮完整词表 logits。Dream 原 hook 会保存完整 CPU logits，需改成即时提取所需统计再释放，并证明记录器不影响采样。
- 全位置 FP32 熵表：64×64 约 16KiB/题，128×128 约 64KiB/题；26000 条、两长度各一半，**纯熵数组约 1GiB**。另需元数据、检查点、临时数据和几十 GB 量级模型缓存；执行前按实际缓存清单核算磁盘，不把 1GiB 当完整空间预算。
- 记录 peak allocated/reserved、系统内存、每题耗时、失败率。拟设峰值不超过实际总显存 90% 为扩池前安全闸门；这是工程阈值，不是论文标准。
- 若 OOM，先修“存完整 logits/累计对象”等观测开销。仍失败则暂停：换更大显存，或授权开独立的 CFG=0/量化/缩短输入偏差实验；不得静默降配后宣称同协议。

环境独立创建，不覆盖 DynHD。原快照为 Python 3.10.18、torch 2.5.1+cu121、transformers 4.53.2；完整 conda 导出有个人路径，不宜照单全装。若实际为 5090 等新架构，torch/CUDA 兼容性可能迫使升级，需记录并跑观察器与生成一致性测试。[环境来源](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/environment.yml>)。

## 7. 标签方案：复现最容易失真的地方

公开 [Qwen 判分器](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/DLLM_generate/metric_qwen.py#L9-L124>) 使用本地 Qwen3-8B，不需要付费 judge API，但其推理占用本地 GPU 时间。

1. TQ/HP 按作者判分提示词和参考答案，用冻结 revision 的 Qwen3-8B、FP16、确定性生成。明确 chat template、thinking 行为和输出长度上限；若为稳定解析新增设置，列为协议偏差，不声称原样重跑。
2. 保存完整 judge 原文、解析状态、原始二值标签。原代码把无法识别的输出也归为错误；保留其代码兼容列，同时设置独立 `invalid` 状态，主报告披露无效数并做纳入/排除敏感性分析。重试规则提前固定，不按分数决定是否重试。
3. 原码 **1=答对**，与常用 **1=幻觉** 相反。统一字段命名 `y_correct` 与 `y_hallucination=1-y_correct`，并用已知对错的玩具样本验证方向。
4. CommonsenseQA 同时保存原宽松规则与严格选项解析结果。规则不一致应报告，不能为接近论文数字而挑 parser。
5. 建议人工抽查每模型每任务 50 题，并覆盖两类、格式失败和 judge 不确定项。需用户/标注者实际执行，不能把第二个模型的意见当真人签核；记录分歧、仲裁和一致率。

原文声称 Qwen 与人类在 TQ/HP 上一致率 90%/84%，这不是本项目已经测出的结果，也不能直接继承为本次标签质量。

## 8. 检测器训练与统计验收

### 8.1 先固定参考配置，再做有上限的验证集搜索

- 参考配置以公开入口为起点：100 epochs，patience=20，batch=64，AdamW、lr=2e-4、weight_decay=0.1，3 层、dropout=0.2，L2 权重=0.1，connect=0。64 长度用 d_pe/feedforward=8，128 用16。这是**代码参考点，不是已知逐格论文最优配置**。
- [另一入口](<https://github.com/chang-sx/TraceDet/blob/356337ac5b95ef6064d0b124f1ef4854440f75b4/train_tuning.py#L42-L76>) 默认 connect=0.05，需与上面差别显式区分，不混合记账。
- 训练 seeds 先定为 `{42,43,44}`，单独保存生成 seed；三次训练不是三次独立重新生成回答。
- 参考配置不足时，预注册最多24个活跃参数组合：lr∈{1e-4,2e-4,5e-4}、dropout∈{0.1,0.2}、层数∈{2,3}、L2权重∈{0.05,0.1}；其余固定。用3 seed平均 dev AUROC 选配置，固定平局规则，记录所有运行。最多72次训练/格，执行预算先经确认。
- 不在 A 中搜索实际未生效的 `gsat_r`。不直接启动原全网格：公开脚本2880组合×3次=8640次训练/格，12格超过10万次；也不能把缩减搜索叫完整论文超参复现。

### 8.2 最少需要的比较

在完全相同的问题、生成和标签上比较：TraceDet、全 T×L 平均熵、无掩码训练版本。无掩码版本须明确聚合和模型容量；不是随便另训一个大网络。TRE、现有 LR/MLP 和 DynHD 属于后续统一协议比较，不能拿旧报告分数横拼成同表。

论文 Table2 的 Dream/TriviaQA/64：无掩码为0.871，高于完整 TraceDet 0.867；因此不预设“掩码在每一格都必须赢”。

### 8.3 指标与检验

- 主指标 AUROC；辅助 AUPRC（同时报告幻觉比例）、balanced accuracy、F1。F1 阈值只在 dev 选择，锁定后应用于 test。
- A 的代码兼容列使用 `AUROC(y_correct, z1)`。若要幻觉正类，则配对反向 `AUROC(y_hallucination, -z1)`；同时另报标准概率版 `p_hallucination=softmax(z)[0]`。两种分数不保证排序一致，必须注明采用哪个分数选 checkpoint/超参，另一种只做预定敏感性分析，不择优报分。
- 按测试问题 bootstrap 10000 次给95% CI；同一问题下各模型/长度/方法保持配对。对训练3 seed先按预定规则汇总逐题分数，再bootstrap，并另报各seed分数与均值/标准差，不把 seed×题目当独立样本。
- 对 TraceDet−基线做配对差值CI；若进行12格正式假设检验，预先指定检验族并用Holm校正。单类test不计算AUROC；筛除/失败数和分母全部公开。
- 第一轮仅一个生成seed，题目bootstrap和3个训练seed不能覆盖生成随机性、judge偏差和协议不确定性；正式结论中明确这点。
- “达到论文数值附近”只作描述：可预定绝对差≤0.05为排查参考线，不是统计等价界，更不是强制刷到的合格线。原表无同协议不确定性，不能因其数值落入本次CI便宣布严格复现。

### 8.4 实际要检验的问题

- H1：在独立测试集上，公开实现是否稳定得到高于随机的检测信号？
- H2：学习时间掩码是否相对平均熵/无掩码有增益？允许部分格无提升。
- H3：在披露协议偏差后，数值与论文是否大致接近？偏离时先查提示词、标签、种子、模型版本和截断，不先归因于论文不可靠。

## 9. 时间与费用：先测，后承诺

当前不能可靠承诺“今晚跑完”或某个固定GPU小时数。P2/P3 记录每模型、每数据集、每长度的平均与P95耗时，再算：

`生成GPU小时 = Σ(各格题数 × 实测秒/题) / 3600`

`总GPU小时 = 生成 + Qwen打标 + 检测器搜索 + 冒烟/重试`

开放式QA的TQ/HP打标约16400条，CSQA约9600条用规则；重试及人工复核另计。硬件计费按实际单价乘GPU小时，模型缓存下载与人工时间单列。不要套用旧DynHD或TRE不同采样协议下的速度。

建议每阶段分别确认上限；P3只授权通路，不默认授权后续26000条采集、24配置搜索、额外生成seed或完整多采样基线。若只能用旧轨迹，则把目标明确改为 C，而不是降低成本后仍宣称完成 A。
