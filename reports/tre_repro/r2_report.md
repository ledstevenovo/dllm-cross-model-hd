## 3. 归因（已核实的机制）

### 3.1 正类率极低，AUROC 的估计基础薄弱

TriviaQA 有上下文吗？没有——模型必须自己知道答案，所以 63.4% 答错。HotpotQA 的答案**就在 distractor 段落里**，8B 模型基本能摘出来：**86.4% 正确**。

后果：正类只有 95 个。AUROC 在正类稀少时方差更大，且 AUPRC（0.22）才是有意义的辅助指标——0.22 在 12% 正类率下相当于随机基线（0.121）的 1.8 倍。

### 3.2 近一半生成撞上预算上限

| 项 | 数值 |
|---|---:|
| 有效长度 = 126（生成上限） | **366 / 786 = 46.6%** |
| 短答（≤20 token）错误率 | 8.2% |
| 长答（≥100 token）错误率 | 17.2% |

有上下文时模型倾向**复述段落**而非简短作答（示例：`"Yes, Couroupita and Graptopetalum plants are both native to Central America. Couroupita, a genus of flowering..."` 一直写到 126 上限）。

TRE 是**全部 128 个生成位置的熵加权和**，所以这 46.6% 的样本大量累加在"复述上下文"的尾部——那部分熵与答案正确性关系很弱。

剔除预算受限样本后：AUROC **0.660**（n=420，32 正例）。**与全量 0.682 接近**，说明截断不是主因，但它确实稀释了信号。

### 3.3 prompt 与题目格式

| 项 | 数值 |
|---|---|
| prompt 版本 | `v4-hotpotqa-context`（R1 是 `v3-bare-question`） |
| prompt 长度 | 均值 1475 token，最大 3715（R1 均值 34） |
| 单题耗时 | 20.1 s（R1 2.8 s） |
| 上游配置 | `distractor`（原文未公开用的是 distractor 还是 fullwiki） |

原文的 HotpotQA 设置未公开到这层细节。**上下文长度差 40 倍**会改变整个熵轨迹的形状：前 1400 多个位置都是上下文，模型在这些位置上的熵模式与"从零生成答案"完全不同。

### 3.4 judge 供应商不同

R2 用 vankit 端点（R1 用 moma）。跨供应商一致性已量化：100 条重判一致率 0.990 / κ 0.979，所以这一点**不足以解释 17.4 pp**，但必须列入差异清单。

## 4. 判读（按预注册规则）

方案 §7 规定：**"不因单次偏差判定方法无效，也不因接近就宣布对齐"**。

本结果的性质：

- **方法有效**：AUROC 0.682 显著优于随机（p=1e-4），说明 TRE 的熵统计在 HotpotQA 上**确实携带正确性信号**；
- **强度低于原文**：−17.4 pp，且远大于 TriviaQA 的 −3.9 pp；
- **最可能的主因**是正类率（12% vs 原文未知但很可能更高）与生成预算（46.6% 撞上限）的交互——两者都源于"有上下文时模型倾向长篇复述"这一与 TriviaQA 根本不同的行为；
- **不建议**为了接近 85.6 而调整生成预算或过滤样本——那会是事后调参。

## 5. 如果要改进（明确标注为未来工作）

| 措施 | 理由 | 代价 |
|---|---|---|
| 提高生成预算到 256 | 让 46.6% 的截断样本自然收尾 | 采集时间 ×2（约 9 h） |
| 改 prompt 要求简短作答 | 减少复述 | 属于新 prompt 版本，须重新冻结 |
| 报告 AUPRC 为主指标 | 正类 12% 时 AUROC 不稳定 | 改变主口径，需事先声明 |
| 补 fullwiki 配置对照 | 原文可能用的是 fullwiki | 需重新下数据、重采 |

这些**都不在本轮执行**，只作为记录。

## 6. 结论一句话

**TRE 在 HotpotQA 上复现出显著但明显更弱的检测能力（0.682 vs 原文 85.6），差距主要来自"有上下文导致长篇复述 + 正类率仅 12%"这一与 TriviaQA 根本不同的生成行为，而不是方法失效。**
