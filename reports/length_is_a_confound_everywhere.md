# "长度"是本项目里最普遍的混杂因素（跨三个数据集一致）

日期：2026-10-24 08:00。汇总本夜所有与长度相关的检验。

## 四组独立证据

| # | 检验 | 结果 |
|---|---|---|
| 1 | TRE 原始分数 vs 归一化 | 同样约 12 token 答案，TRE 中位在 L64/L128/L256 下为 **9.6 / 20.0 / 39.6** |
| 2 | 检测器去长度特征 | LLaDA/TQ 0.852 → **0.843**（与 TRE 0.843 持平）；Dream/HotpotQA 0.858 → **0.683**（掉 0.175） |
| 3 | 上下文效应长度匹配 | LLaDA 匹配 1–20 token 后差距 **0.176**（比全量的 0.093 更大） |
| 4 | `effective_length` 单独作分数 | 在多个格上 AUROC **0.40–0.66**，本身就有判别力 |

## 结论

**长度在本项目里几乎无处不在**：

- 它影响 TRE 的**尺度**（求和项数）；
- 它是检测器 **10 维特征的主要方差来源**（Dream/TriviaQA 上 10/10 特征 |r|>0.25）；
- 它对**标签有预测力**（答错的往往更长）；
- 它还**扭曲跨条件的比较**（开卷 vs 闭卷的原始差距被它掩盖）。

## 因此本项目的四条报告规则

| 规则 | 理由 |
|---|---|
| 报告 TRE 必须同时给**截断率** | 截断是长度的极端表现，方向不定地影响 AUROC |
| 跨预算比较必须用 `tre_length_normalized` | 原始求和随位置数缩放 |
| 检测器对比应说明**是否含长度类特征** | 否则会把长度效应误认为熵特征优势 |
| 分层报告应含**答案长度分布**（中位/p95） | 同一 AUROC 在长短答案场景含义不同 |

## 与既有文献的关系

TRE 原文（arXiv 2510.xxxx）以**原始求和**报告，未讨论长度归一化。
本项目的发现是：**原始求和跨预算不可比**，但**同预算下与原文对照仍有效**
（所有 4 个可比格子都是 128 预算，尺度相同）。

所以本项目的复现结论不受这条影响，但**若要在其他预算上使用 TRE，必须归一化**。
